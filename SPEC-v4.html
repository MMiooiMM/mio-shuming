數名其妙 v4

可分享的產品外殼 — 開發・驗證・review 的唯一判準

2026-09-13 使用者確認凍結

背景

v1–v3 的計算引擎與出處追溯已完成，缺的是「讓人看得懂、敢分享、傳得開」的產品外殼。本輪定位為可分享的個人作品：親友之間（多半經 LINE 傳給家人長輩）用得順、看起來專業；不經營搜尋流量。

A. 分析卡片（分享）

  1. 分析結果區提供「分享卡片」按鈕，以前端 Canvas 繪製 PNG，不新增執行期依賴套件。
  2. 卡片內容：姓名、生日（年月日）、生肖、四柱干支；外加分項標籤並列（三才、五格各格、生肖喜忌字根、用神匹配）——每項各自一個判定，不計數、不加總。
  3. 卡片不印時分、出生地。未填時辰時，四柱與八字相關標籤不出現。
  4. 卡片底部固定印：站名＋網址＋「僅供參考」。
  5. 支援 Web Share（含檔案）的裝置叫出系統分享選單；不支援時退回下載 PNG。兩條路徑都要有 E2E 或實機證據。
  6. 立春當日未定生肖等不確定情況，卡片據實呈現兩種可能，不擅自選一個。
  7. 網址不帶任何使用者輸入——全站不寫入 query／hash。
為什麼不做分享連結：出生日期、時辰、出生地寫進網址會留在聊天記錄與瀏覽紀錄；改由使用者提出的圖片卡片分享，個資只印必要欄位。

B. 結果摘要與名詞解釋

  1. 分析結果頂端有摘要區，與卡片使用同一組分項標籤（同一個產生函式）。
  2. 名詞（人格、天格、地格、外格、總格、三才、用神、十神、藏干、真太陽時等）可就地點開說明；滑鼠與鍵盤（Enter／Space）皆可展開收合，並具正確的 aria-expanded。
  3. 解釋文字集中於 src/data/ 資料檔，不寫死在 UI 程式裡。

C. 收藏比較（取名模式）

  1. 收藏資料加存預產期；舊的 mio-shuming:favorites:v1 資料仍可讀取。無預產期的舊收藏，生肖標籤顯示「未知」，不猜。
  2. 可勾選 2–5 個收藏並排比較：各名字的三才、五格（僅列取名可改變、計吉凶的格）、生肖喜忌字根標籤。
  3. 比較結果可輸出比較卡片（輸出方式同 #5）；卡片只印生肖、不印預產期；預產期在立春 ±3 週內則印兩個生肖。

D. 聲明

  1. 頁尾常駐免責與隱私聲明，內容含：所有計算在裝置上完成、不上傳；收藏只存在此瀏覽器；命理結果僅供參考。
  2. 兩種模式的出生資料表單旁，各有一行「資料只在你的裝置計算，不上傳」。

E. 分享預覽

  1. index.html 補上 OG／Twitter card meta、favicon、apple-touch-icon；OG 圖為固定圖片。以 LINE 或 FB 的預覽除錯工具實際抓取，截圖當證據。

F. 品質門檻

  1. 新增 Playwright E2E，在寬度 390px 與 1280px 各跑一遍：兩模式主流程、分析卡片、收藏比較與比較卡片、名詞解釋的鍵盤操作。
  2. CI 流程為 npm test → Playwright → build，全過才部署；任一失敗即不部署。
  3. 首頁、分析結果、取名結果三種狀態的 Lighthouse 無障礙分數皆 ≥ 95，附報告數字當證據。
  4. 390px 寬時整頁不可橫向捲動（表格限於自身容器內捲動），以 Playwright 斷言 scrollWidth <= clientWidth 驗證。
  5. 既有 vitest 全數通過；動到畫面外觀的部分須走 /mio-mirror。

G. UI 收斂第一輪（2026-09-13 追加凍結）

來源：docs/design-review/2026-09-13-external-ui-critique.md「只能改三件事」第 1 項；範圍由使用者裁決。改動前截圖：docs/evidence/v4-walkthrough/（HEAD 7c39bf2）。

  1. 三級按鈕：主要實心 accent；次要 surface 底、1.5px accent 框、accent 字；文字無底色、ink-soft 字、hover 加底線。小按鈕統一高 36px、左右 padding 14px、圓角 8px。
  2. 按鈕分配：主要為列出吉筆畫組合、開始分析、比較勾選的名字、分享卡片；次要為帶入完整分析、收藏這個名字、輸出比較卡片；文字為移除。用神覆寫切換鈕不再用綠色，選中狀態改用 accent-soft 底。模式切換大卡不動。
2026-09-13 修正（H 節 #35、#33）：#23 原把「分享卡片」列主要、「輸出比較卡片」列次要，同為匯出圖卡卻分兩級，兩者統一為次要。「選中狀態改用 accent-soft 底」由 #33 取代：選中態一律實心 accent 配白字，因為粉紅與凶／忌同色系。
  1. radio 與 checkbox 使用 accent-color: var(--accent)。
  2. 新增中性灰 token：淺色模式底 #EEEBE6、字 #6B645A（對比 4.91:1）；深色模式另訂，對比須 ≥ 4.5:1。「中性」「不計」「生肖未知」與用神五行標籤改用灰色；黃色只留給半吉與喜忌並見。
  3. 候選字 chip：中性字白底加 1px line 框、ink 字；喜字維持綠、忌字維持紅；選中為實心 accent。
  4. 兩張分享圖卡的中性色改為同一個灰；版式與 chip 形狀不動。
  5. 兩模式所有結果狀態、名詞說明全部展開、收藏與比較視圖、頁尾、資料來源區塊的畫面文字（innerText），不得含 SPEC、localStorage、curl、kTotalStrokes、kRSUnicode、$comment、tools/、src/。「localStorage」改寫為「只存在這台裝置的瀏覽器」；Unicode／Unihan 等引用來源名稱保留。
  6. 人工整理的資料檔直接改寫出處備註的措辭：原文引文一字不改，只改描述查證方式的開發者用語。由腳本產生的資料檔，改生成腳本後重新產生，不手改。
  7. 新增 Playwright 守衛：走完 #28 列的所有狀態後讀取 innerText，斷言不含上述字詞。須做變異測試：放回一個禁用字，測試要紅。
  8. 既有 vitest 與 E2E 全數通過；Lighthouse 三態無障礙分數仍 ≥ 95；以 mirror-shots 拍 390／1280 前後對照截圖，並再跑一次 /mio-mirror。
本輪不做：結果優先與降噪、手機排版破損、網頁與圖卡 chip 形狀統一、圖卡版式。

H. UI 收斂第二輪（2026-09-13 追加凍結）

來源：docs/design-review/2026-09-13-external-ui-critique-round2.md。專修 G 節條文本身造成的問題（#23 匯出鈕分級、選中態借粉紅、#28 禁用字列舉不全）；範圍由使用者裁決。

  1. 模式分頁改為 segmented control：外框底 #ECE8E2、padding 4px、圓角 12px；選中項為 surface 底、accent 字、淡陰影；未選項為透明底、ink-soft 字（6.01:1）。深色模式另訂，對比 ≥ 4.5:1。保留 aria-pressed。
  2. 選中態通則：所有切換鈕的選中態一律實心 accent 配白字（8.26:1），不得使用任何語意色淡底。先套用到用神覆寫開關。
2026-09-13 實作註記（B14，#33）：「白字」在深色模式改用 surface 色：深色 accent 是淺色的 #e2856f，配白字對比只有 2.68:1，沿用 .chip--on 前例後為 6.17:1；淺色模式仍是白字。同一條通則也套用到「?」名詞說明鈕的展開狀態，它原本也用 accent-soft 底。
  1. 名詞說明框改用中性底 #F3F1EC（內文 15.02:1，深色模式另訂），保留左側 3px accent 線。
  2. 「分享卡片」與「輸出比較卡片」統一為次要（外框）。
  3. 畫面文字不得含內部文件路徑、內部欄位名（如「資料檔的 conflicts」）或 Markdown 語法；資料檔存純文字、UI 不做 Markdown 渲染。上游檔名與欄位名改用人話名稱；來源連結 href 不變，連結文字改為網域加 ↗。由腳本產生的資料檔依 #29 改生成腳本後重新產生。
  4. 禁用字守衛保留原列舉，並在同樣 12 個狀態加入類別規則：檔案路徑、檔名、Markdown 粗體、Unicode 欄位名（k[A-Z]…）、conflicts；每個類別各做一次變異測試。
  5. 同類元件一致性測試：E2E 斷言「分享卡片」與「輸出比較卡片」的 background-color、border-color、color 計算樣式完全相同。
  6. vitest 與 E2E 全數通過；Lighthouse 三態無障礙 ≥ 95；390／1280 前後對照截圖；第三次 /mio-mirror。
本輪不做：資料來源收合與降噪、送出後結果優先、比較表裁切、chip 形狀統一、圖卡版式、「三才　三才」標籤重複。

I. 資料來源收合與識別碼清除（2026-09-13 追加凍結）

來源：docs/design-review/2026-09-13-external-ui-critique-round3.md 第 4 節第 1、2 項與第 30 行；範圍由使用者裁決。

評審第 2 項「送出後結果不在第一屏」不成立：評審看的是整頁截圖，看不到捲動位置。實測兩個模式、390 與 1280 兩種寬度，成功送出後結果頂端都在視窗 0px。真正的缺口只有取名模式出錯時不捲動（#45）。
  1. 兩個模式的資料來源區塊改為 <details>，預設收合；摘要列「資料來源（N 項）」，N 由實際列數計算；摘要列沿用 .combo > summary 樣式，不新增元件；展開後內容不刪減，本輪不做獨立來源頁。
  2. 取名結果頂部卡片的「出處：https://…」改為與 #36 相同的網域加 ↗ 連結。
  3. 畫面文字中的 repo 名（ben-hua/general_standard_chinese、zhenyangze/chinese-wuxing）、碼位 0xA440–0xC67E、CHISE 網址改寫為人話；依 #29 改生成腳本後重產，逐欄比對只有這些欄位變動。
  4. 禁用字守衛新增三個類別規則：裸網址、owner/repo（兩段都以英文字母開頭）、0x 碼位；各做一次變異測試。
  5. 「頁尾與資料來源」狀態先展開 details 再讀文字（收合內容不在 innerText 裡）；變異測試證明拿掉展開步驟就抓不到注入的違規字。
  6. 取名模式出錯時（日期無效、姓氏查無）也捲到訊息，與分析模式一致。
  7. E2E 在 390 與 1280 斷言：兩個模式的成功與出錯，送出後結果頂端都在視窗內。
  8. vitest 與 E2E 全數通過；Lighthouse 三態無障礙 ≥ 95；390／1280 前後對照截圖；第四次 /mio-mirror。
本輪不做：選中態改墨色、比較表裁切、送出後表單收成摘要列、chip 形狀統一、圖卡版式、「三才　三才」標籤重複。

J. 摺疊列統一（2026-09-13 追加凍結）

來源：docs/design-review/2026-09-13-external-ui-critique-round4.md 第 2 段第 ② 項；範圍由使用者裁決。起因：I 節 #40 要資料來源沿用 .combo 樣式，把它沒有展開指示的缺陷一起繼承了；本節先定義元件，再規定誰使用。

  1. 摺疊列：資料來源與筆畫組使用同一個元件；整列可點、最低高度 48px；右側 16px chevron（ink-soft），展開旋轉 180°；hover 底色 bg；:focus-visible 顯示 2px accent 外框；不新增色碼。
2026-09-14 實作註記（B19，#48）：桌機摺疊列用 grid、chevron 為最後一欄，標籤包進 .combo__tags 整群靠右換行（第一版絕對定位＋右側 2.2rem padding 讓 1280 寬 16 列都掉一顆標籤到第二行靠左）；手機 ≤30rem 改回流動排列＋絕對定位 chevron、padding-right 1.9rem（grid 會讓每列 74→102px）；資料來源卡 padding 0＋overflow hidden 讓整張卡可點，聚焦外框畫在內側。
  1. 框線：摺疊列本身不加框，列與列之間用 1px line 分隔線；資料來源卡只有一列，整張卡就是那一列。
  2. 次要摺疊（生肖忌字）：維持小字文字樣式，加 12px chevron 與同樣的展開旋轉。
  3. 旋轉動畫 150ms；prefers-reduced-motion: reduce 時不做動畫。
  4. E2E 類別規則：390／1280 所有結果狀態下，每一個 details > summary 都有可見 chevron，展開前後 transform 不同；同一變體的 chevron 顏色、尺寸與 summary padding 計算樣式相同。變異測試：拿掉任一變體的 chevron，測試要紅。
  5. vitest 與 E2E 全數通過；Lighthouse 三態無障礙 ≥ 95；390／1280 前後對照截圖；第五次 /mio-mirror。
本輪不做：分析頁細節預設收合、筆畫組展開後的三層框與標籤換行、比較表裁切、圖卡上的網址、選中態顏色。

沿用原則（v1–v3 全數繼承）

不合成單一總分；每條規則出處寫進資料檔 source 欄位並於「資料來源」呈現；流派衝突不擅自調和；引擎純函式；罕字與範圍外據實回報不猜；GPLv2。

Out of Scope

網址帶參數分享或重算、列印版面、SEO 靜態頁、流量統計、回饋管道、字義與讀音資料、候選字排序改良、PWA 與離線、國際化。
